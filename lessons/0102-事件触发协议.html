📡 第 0102 课：事件触发协议

内部攻击下的 CPS 安全估计 ⏱ 阅读时间：25 分钟 📄 精读课程 · 第 2 课 / 共 7 课
🎯 本课目标：理解事件触发传输协议的工作原理——确定性触发和随机性触发两种机制如何决定传感器数据是否发送，以及它们对估计误差协方差的影响。

1. 从 Kalman 滤波到事件触发

上节课我们学习了 Kalman 滤波的基本框架：传感器在每个时刻 $k$ 测量系统状态 $x_k$，远程估计器接收测量值 $y_k$ 后执行预测-更新两步循环。但在 CPS（信息物理系统）中，通信资源是有限的——无线信道带宽有限，传感器电池有限。每时每刻都发送数据既浪费资源，也容易被攻击者发现。

💡 核心思想：当"没有什么新鲜事"时，就不发送数据。只有创新（innovation）足够大时才触发传输，从而大幅降低通信率。

定义时刻 $k$ 的创新（innovation）为：

$\varepsilon_k = y_k - C \hat{x}_{k|k-1}$

其中 $\hat{x}_{k|k-1}$ 是上一时刻对当前状态的预测。创新衡量了实际测量值与预测值之间的偏差——如果 Kalman 滤波预测得准，创新就小，意味着没有新的信息需要传输。

2. 传输决策变量 $\gamma_k$

设二进制变量 $\gamma_k \in \{0, 1\}$ 表示时刻 $k$ 是否发送测量数据：

$\gamma_k = \begin{cases} 1, & \text{发送测量值 } y_k \\ 0, & \text{不发送} \end{cases}$

事件触发协议的核心就是设计一个触发条件，根据创新 $\varepsilon_k$ 决定 $\gamma_k$ 的值。

3. 超时机制

⚠ 防止"饿死"：如果通信信道一直不出问题，可能出现长时间不发送数据的情况，导致远程估计器对系统状态完全失明。因此引入超时计数器 $\tau_k$。

超时计数器 $\tau_k$ 记录了自上次成功传输以来经过的时间步数：

$\tau_{k+1} = \begin{cases} 0, & \gamma_k = 1 \\ \min(\tau_k + 1, \hbar), & \gamma_k = 0 \end{cases}$

其中 $\hbar$ 是最大超时阈值。当 $\tau_k$ 达到 $\hbar$ 时，传感器强制发送数据（$\gamma_k = 1$），防止长时间无通信。

4. 确定性触发协议

确定性触发协议（Deterministic Triggering）的触发集合定义为：

$\Xi_k^d = \{ \varepsilon_k \mid \|\varepsilon_k\|_\infty \le \delta \}$

其中 $\delta > 0$ 是人为设定的阈值参数。传输规则是：

$\gamma_k = \begin{cases} 0, & \varepsilon_k \in \Xi_k^d \;(\text{创新小，不发}) \\ 1, & \varepsilon_k \notin \Xi_k^d \;(\text{创新大，发}) \end{cases}$

直观理解：如果创新 $\varepsilon_k$ 的每个分量绝对值都不超过 $\delta$，说明 Kalman 滤波预测得足够好，不需要发送数据。否则，创新太大，必须发送让估计器修正。

4.1 通信概率 $p_d$

在确定性协议下，通信概率（即 $\gamma_k = 1$ 的概率）与 $\delta$ 直接相关。假设创新服从高斯分布 $\varepsilon_k \sim \mathcal{N}(0, K_k S_k K_k^\top)$，其中 $K_k$ 是 Kalman 增益，$S_k$ 是创新协方差，则：

$p_d = 1 - \big[ 1 - 2Q(\delta) \big]^r$

其中 $r$ 是测量向量的维度，$Q(\cdot)$ 是标准正态分布的尾部概率函数：

$Q(x) = \frac{1}{\sqrt{2\pi}} \int_x^\infty e^{-t^2/2} dt$

标量情况（$r = 1$）下公式简化为：

$p_d = 2Q(\delta)$
理解关键：$\delta$ 越大，$Q(\delta)$ 越小→通信概率越低。更大的阈值意味着更宽松的"不发送"条件，通信更节省。反之，$\delta$ 越小，通信越频繁。

5. 随机性触发协议

确定性触发的缺点是攻击者可以预测——知道 $\delta$ 就知道哪些创新值会触发传输。随机性触发协议引入随机化，让触发条件不可预测。

随机性触发协议（Stochastic Triggering）的触发集合定义为：

$\Xi_k^s = \{ \varepsilon_k \mid \zeta_k \le \exp(-\tfrac{1}{2} \varepsilon_k^\top \Pi \varepsilon_k) \}$

其中 $\zeta_k \sim \mathcal{U}[0, 1]$ 是均匀随机数，$\Pi \succ 0$ 是一个正定矩阵参数。传输规则：

$\gamma_k = \begin{cases} 0, & \varepsilon_k \in \Xi_k^s \\ 1, & \varepsilon_k \notin \Xi_k^s \end{cases}$

这里的决策是概率性的——即使创新相同，两次实验也可能做出不同的传输决策，因为 $\zeta_k$ 每次随机独立抽样。

🎯 直觉理解：确定性能让你知道"多大的创新一定会触发传输"；随机性则让传输决策变得不可预测——给定同样的创新值，可能发也可能不发，攻击者无法建立确定性的对应关系。

5.1 通信概率 $p_s$

随机性协议下的通信概率为：

$p_s = 1 - \frac{1}{\sqrt{|I + K Z K^\top \Pi|}}$

其中 $Z = C P_{k|k-1} C^\top + R$（即 $S_k$），$K$ 是 Kalman 增益。这个公式来自高斯分布的概率积分。

6. 两种协议的误差协方差

6.1 确定性协议下的误差协方差

当使用确定性事件触发协议且通信正常时，误差协方差为 $P_k^d$（记为式 13）：

$\displaystyle P_k^d = P + \frac{\delta}{\sqrt{2\pi}} e^{-\frac{\delta^2}{2}} Q^{-1}(\delta) \big[ h^{\tau_k}(P) - P \big]$

该公式表明，误差协方差由两部分组成：

  • $P$：理想 Kalman 滤波（每次都通信）的稳态误差协方差
  • $h^{\tau_k}(P)$：连续 $\tau_k$ 步未通信后，开环预测的误差协方差
  • 中间项是加权系数，反映了由事件触发引入的额外不确定性

6.2 随机性协议下的误差协方差

Lemma 2（随机触发误差协方差）：在随机性事件触发协议下，远程估计器的误差协方差为：

$\displaystyle P_k^s = P + \frac{1}{\sqrt{|I + K Z K^\top \Pi|}} \Big[ \Phi\big((I + K Z K^\top \Pi)^{-1/2} \varepsilon_k\big) - P \Big]$

（此处 $\Phi(\cdot)$ 表示高斯累积分布函数相关的矩阵变换，完整公式参见论文 Lemma 2。）

7. 两种协议的对比

特性 确定性触发 $\Xi_k^d$ 随机性触发 $\Xi_k^s$
触发条件 $\|\varepsilon_k\|_\infty \le \delta$ $\zeta_k \le \exp(-\tfrac12 \varepsilon_k^\top \Pi \varepsilon_k)$
参数 阈值 $\delta$ 矩阵 $\Pi$
通信概率 $p_d = 1 - [1 - 2Q(\delta)]^r$ $p_s = 1 - 1/\sqrt{|I + KZK^\top\Pi|}$
可预测性 高——给定 $\varepsilon_k$，$\gamma_k$ 完全确定 低——即使知道 $\varepsilon_k$ 也无法确定 $\gamma_k$
安全性 低——攻击者可以精确计算触发时刻 高——随机化使攻击者难以预测
实现难度 简单——只需比较 $\varepsilon_k$ 与 $\delta$ 稍复杂——需要生成 $[0,1]$ 均匀随机数

📝 练习

✏️ 练习 1：不同 $\delta$ 下的通信概率

假设标量测量（$r = 1$），$\varepsilon_k \sim \mathcal{N}(0, 1)$。计算以下阈值下的通信概率 $p_d$：

  1. $\delta = 0.5$
  2. $\delta = 1.0$
  3. $\delta = 2.0$
  4. $\delta = 3.0$
📖 查看解答

使用 $p_d = 2Q(\delta)$：

  • $\delta = 0.5$：$p_d = 2 \times 0.3085 = 0.617$（约 62% 时间通信）
  • $\delta = 1.0$：$p_d = 2 \times 0.1587 = 0.317$（约 32% 时间通信）
  • $\delta = 2.0$：$p_d = 2 \times 0.0228 = 0.046$（约 4.6% 时间通信）
  • $\delta = 3.0$：$p_d = 2 \times 0.0013 = 0.0026$（约 0.26% 时间通信）

规律：$\delta$ 每增加约 1，通信概率下降一个数量级。$\delta = 2$ 时已可将通信率降至 5% 以下，大幅节省带宽。

✏️ 练习 2：直觉对比两种协议

判断以下说法是否正确：

  1. "确定性触发协议的通信概率仅取决于 $\delta$，与系统动态 $A$ 无关。"
  2. "随机性触发协议下，即使是很大的创新值，也有可能不被发送。"
  3. "确定性协议更容易被攻击者利用，因为给定创新值，攻击者可以精确知道传输是否发生。"
  4. "随机性协议的超时机制与确定性协议不同。"
📖 查看解答
  1. 正确。$p_d = 2Q(\delta)$（标量）只依赖于 $\delta$，系统动态 $A$ 不影响通信概率，影响的是创新本身的分布。
  2. 正确。因为 $\zeta_k \sim \mathcal{U}[0,1]$ 是随机的，即使 $\exp(-\tfrac12\varepsilon_k^\top\Pi\varepsilon_k)$ 很小，只要有 $\zeta_k$ 恰好小于它，就判定为"不发"。但创新越大指数项越小，不发送的概率也越低。
  3. 正确。这是确定性协议最大的安全缺陷——攻击者只要知道 $\delta$，就能精确预测每一个传输事件。
  4. 错误。超时机制完全独立于触发协议，两种协议共用同一个超时计数器 $\tau_k$ 和最大超时阈值 $\hbar$。

🔗 本课小结

📌 要点回顾：
  1. 事件触发协议通过有选择地发送测量数据来节省通信资源。
  2. 创新 $\varepsilon_k$ 是触发决策的核心——新鲜事才上报。
  3. 超时机制 $\tau_k$ 防止长时间无通信导致的失明。
  4. 确定性协议简单但可预测，通信概率 $p_d = 1 - [1 - 2Q(\delta)]^r$。
  5. 随机性协议引入随机化增强安全性，通信概率 $p_s = 1 - 1/\sqrt{|I + KZK^\top\Pi|}$。
